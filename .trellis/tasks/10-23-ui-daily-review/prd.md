# 重构公共导航与每日复盘界面

## Goal

让第一次使用慎独的人进入每日复盘后，立即知道主要动作是开始或继续今日复盘；通过聚焦式书写和克制的玻璃质感降低信息负担，同时保留熟悉用户的操作效率与原有数据行为。

## Background and confirmed facts

- 仓库是原生 HTML/CSS/JavaScript 单页应用，页面由 `shendu/public/app.js` 渲染，样式在 `shendu/public/styles.css`，服务端在 `shendu/server.mjs`。登录后默认进入 `daily`。
- 当前每日页在引言、三张统计卡、工具条之后，一次渲染证据、反思、行动、日记四个书写区。左侧导航与右侧阶段进度、日历、待验证行动同时可见。
- 当前草稿由显式保存按钮写入；离开时有未保存提醒。完成后永久锁定，历史周期只读。设置支持六套主题、自定义颜色及减少动态效果，窄屏有导航抽屉。
- 已恢复 GitHub `main` 的正式 Git 检出，基线提交为 `e24da0371b4b08701137744db6ac677391667e3f`；本任务文档与规范已迁入该检出。

## Requirements

| ID | Requirement |
|---|---|
| R1 | 重构公共导航和每日复盘页。首次视窗突出“开始／继续今日复盘”；统计与其他辅助内容降为次要层级。其他复盘页的业务内容暂不重做。 |
| R2 | 左侧导航把六类复盘归为一组，历史、行动验证、备份和设置降为次级入口；所有现有入口仍可到达，当前所在位置明确。 |
| R3 | 每日复盘一次聚焦一个书写区，但有总览可自由跳至证据、反思、行动、日记任意区，并显示已填写／待填写状态；不可强制按顺序完成。 |
| R4 | 阶段进度、日历和待验证行动移入易打开的辅助面板，书写区成为主内容；这些功能在桌面与手机上都可到达。 |
| R5 | 保留手动保存、未保存状态提示、离开提醒、必填校验、完成确认、永久锁定、历史只读及记录版本冲突等既有行为。切换书写区不得丢失未保存输入。 |
| R6 | 视觉保留安静、适合思考与书写的产品气质。默认采用明亮、低对比抽象光色背景与少量克制的半透明玻璃面板；清晰度和可读性优先。 |
| R7 | 保留原生 HTML/CSS/JavaScript 技术栈、六套主题、自定义颜色、手机导航和减少动态效果。 |
| R8 | 实施前先形成信息层级和视觉方案；实施后用实际桌面和手机页面截图及关键操作检查验收。 |

## Acceptance criteria

- [x] AC1 (R1, R6): 登录后的每日页首屏明确呈现当前复盘状态与一个主要动作；不再同时展示三张统计卡及四个完整书写区。视觉层次在浅色默认主题下清楚，玻璃效果只用于少数主面板。
- [x] AC2 (R2): 六类复盘、历史、行动验证、备份、设置与账户相关入口仍可通过导航到达；桌面与手机都能识别当前位置。
- [x] AC3 (R3, R5): 新建或继续草稿时可自由切换四区并返回总览；填写状态可见；切换后输入原样保留，保存后重新打开仍保留。
- [x] AC4 (R4): 阶段进度、日历及待验证行动在桌面与手机上均可通过辅助面板查看和操作，且不遮断主书写流程。
- [x] AC5 (R5): 手动保存、未保存提示、离开提醒、缺失必填反馈、完成确认、永久锁定、历史只读及版本冲突反馈保持可用。
- [x] AC6 (R6, R7): 默认主题、六套预设与自定义颜色下，正文、表单、状态和焦点都可辨认；窄屏布局不横向溢出；系统及用户减少动态效果设置生效。
- [x] AC7 (R8): 方案包含信息层级与视觉规则；实施验收留有桌面和手机截图，并记录关键路径检查结果。项目的 `npm run check` 通过；如改变服务端契约，再运行 `npm test`。

## Out of scope

- 重做每周、每月、90 天、年度、重大决策的业务表单；它们仅随公共导航和共享外壳发生必要变化。
- 自动保存、数据库结构、加密、账号权限或复盘 API 语义的修改。
- 引入 React、Vue、构建工具或新路由框架。
- 本规划阶段的产品代码修改、部署、推送。

## Decisions and deferred work

访谈已确认：新用户优先但保留老用户效率；浅色克制玻璃；自由跳转的聚焦书写；手动保存；辅助信息收起；原生栈与现有主题/手机能力保留。其他复盘页可在首个任务验证后沿用设计系统，作为后续独立任务规划。
