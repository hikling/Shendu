## 关键路径

| 验收点 | 结果与证据 |
|---|---|
| 首屏层级 | 桌面与 390px 手机首屏均先见日期、状态和唯一主要动作；四区目录在首屏可见。三张统计卡不再占每日首屏。 |
| 自由切区、草稿 | 从“开始今日复盘”进入证据，填写后切到反思再返回，原 DOM 输入保留；目录从待填写变为已填写。保存前离开每日页出现继续/放弃对话框。显式保存后重开，内容恢复。 |
| 完成与只读 | 缺必填时提示具体字段；填齐后显示永久锁定确认。完成后相应表单禁用，从历史再次打开仍只读，可自由查看四区。 |
| 辅助面板 | 桌面和手机的“辅助信息”可打开阶段进度、日历和待验证行动；Escape 关闭并将焦点送回入口。 |
| 其他导航 | 每周、每月、历史、行动验证、备份、账户管理均实际打开；手机抽屉可展开并通过遮罩关闭。90 天入口依原阶段配置条件显示。 |
| 主题与响应式 | 六套预设均可在主题设置中切换；另保存自定义蓝色主色和减少动态效果后检查手机首屏。实际检查约 1440px、820px、390px 布局；未见横向溢出，浏览器错误日志为空。 |
| 版本冲突 | 在另一会话把本地测试草稿更新到新版本后，旧页面保存显示“这条记录已在其他设备更新，请刷新后再继续”。 |
| 会话失效与恢复 | 在一页保留未保存文字，另一页退出测试账户；原页保存时出现“登录已失效”对话框，DOM 输入未丢失。重新登录后再次点击保存，草稿成功写入。 |
| 设置入口的未保存保护 | 写入测试文字后点击设置，出现原有“这页还有未保存内容”对话框；选择放弃后重新渲染草稿，输入确实清空，再进入设置。 |
| 长文案与更窄视窗 | 将每日问题 1 改为较长中文句子，在 320px CSS 视窗检查换行与表单；`documentElement.scrollWidth` 等于 320px，没有横向溢出。320px 重排可覆盖高缩放常见的窄内容宽度，但未单独测试浏览器原生 200% 缩放。 |
| 最终版辅助面板键盘 | 最终资源版本 `5.5.4-ui7` 下，打开面板后焦点落在关闭按钮；Shift+Tab 循环到面板最后一个可操作日期，Escape 关闭并把焦点返回“辅助信息”。 |

## 静态检查与范围

最终版 `npm run check` 与 `git diff --check` 通过，浏览器控制台无 error/warn。`premium-audit-final.json` 是严格模式静态审计原始输出：退出码 2、14 项，原版基线为 15 项。14 项包括 11 个“无动作按钮”（实际由 `bindCommon()`、`bindReview()` 等 JavaScript 绑定，运行时已逐项检查相关路径）、2 个 textarea resize 检测（每日书写区 CSS 已设 `resize:none`，其余旧表单沿用原有规则）和 1 个原生 select 所有权未声明（项目采用原生状态下拉，已写入 `.trellis/spec/frontend/ui-quality.md`）。审计脚本只检查 HTML 字面属性，不解析事件绑定或关联 CSS，因此这些静态提示未作为新增功能故障处理。服务端 API、数据库与持久化契约没有修改，本任务未运行服务端安全/备份测试套件。
