# 技术与交互设计：公共导航和每日复盘

## Boundaries

只改浏览器界面的布局、交互和样式，主要文件为 `shendu/public/app.js`、`shendu/public/styles.css`，必要时调整 `shendu/public/index.html`。保持 `shendu/server.mjs` 的 API、SQLite 模式、记录状态与加密行为不变。共享外壳影响所有页面，因此需检查其他路由的导航可用性，但它们的业务表单不在本任务重做范围。

## Information hierarchy

1. 公共外壳：品牌与当前页、按“复盘 / 记录与验证 / 数据与设置”组织的导航、清楚的当前位置。
2. 每日页首屏：今日复盘状态、一个主要动作（开始或继续）、简短的进度总览。统计信息不占首屏主视觉。
3. 书写区：证据、反思、行动、日记四区只显示当前区的完整表单。总览展示四区名称与填写状态，可自由切换，无强制步骤门槛。
4. 辅助面板：阶段进度、日历、待验证行动由显式入口打开；桌面和手机均可操作，关闭后焦点回到入口。

总览的“已填写”仅表示出现非空输入，不代表完成校验通过。最终完成仍以现有 `validateCurrent()` 和服务端校验为准。

## Local state and input preservation

每日当前区是纯浏览器展示状态，不进入记录 payload。优先保留四区 DOM，只切换可见性与 `aria` 状态；这样用户切区时表单节点和输入不被重建。若实现过程中必须重渲染，先用 `collectCurrent()` 收集值，并保留 `state.dirty`，避免 `renderReview()` 默认重置 dirty 的副作用。区内输入继续由 `bindReview()` 标记 dirty；区切换不得调用 `saveCurrent()`，也不得跳过 `attemptNavigate()` 对真正路由离开的保护。

保存仍由显式按钮触发 `PUT /api/records`。完成路径仍先 `validateCurrent()`，再确认并锁定。锁定或历史记录可通过同一四区导航阅读，但没有编辑入口。版本冲突、会话过期与错误提示继续使用既有 `request()`/toast/对话框通道。

## Shared navigation and auxiliary panel

在 `sidebar()` 和 `navItems()` 中组织现有路由，不改变路由名或权限判断。设置与账户动作保持可达。导航项以当前 `state.route` 表示选中；移动抽屉沿用现有按钮和关闭行为。

`rightRail()` 保留阶段、日历、待验证行动内容，改成按需展开的辅助面板。入口、关闭按钮、Escape、焦点返回和 `aria-expanded` 要一起设计；日历按钮仍经过 `attemptNavigate()`。不要以 CSS 隐藏内容后失去键盘访问路径。

## Visual system

先用灰阶线框确认层级，再确定颜色、排版、玻璃材质。默认浅色：低对比抽象光色背景，少量半透明主面板，清晰边框和轻阴影；密集表单区保持稳定、易读的书写底色。新增玻璃相关 CSS 变量与现有 `--primary` 等主题色并存，六套预设和自定义色均须可读。没有 `backdrop-filter` 时有不透明回退；遵守系统及设置中的减少动态效果。视觉表达保留安静的复盘气质，不用大量发光卡片或无语义装饰。

## Compatibility and risks

- `app.js`、`styles.css` 文件较大且以模板字符串和级联样式组织。新增规则需避免选择器覆盖冲突及全局变化波及其他页面。
- 改变共享外壳会影响历史、行动、备份、账户页，至少检查其导航、宽度、面板和主题状态。
- 首个任务不迁移数据，也不新增自动保存。若后来发现需要持久化“当前区”，应另行评估产品和数据契约。
- 正式 Git 检出已恢复；本任务在基线 `e24da0371b4b08701137744db6ac677391667e3f` 上实施，保留独立的源码快照备份。
